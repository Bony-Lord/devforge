# План исправлений и проверок DevForge

Обновлён: 2026-10-31. Основная версия — Electron, Windows. Нативная ветка
сохранена отдельно; перенос без Chromium отложен. Оформление и поведение оконника
сохраняются. Изменение исходников, прохождение теста и установка обновления —
отдельные этапы: выполненный этап не подтверждает следующие.

## Alpha.6: единственный оконный интерфейс Windows

- [x] Dockview включён в основной Windows-пакет и загружается независимо от профиля аддонов.
- [x] Упрощённый режим отсутствует в настройках приложения и проекта; старое `simple` мигрирует в `windows` без смены темы и геометрии.
- [x] Оконник убран из установок и удаления дополнений. Старый ID читается как пустой совместимый alias; наборы и сохранённые профили не ломаются.
- [x] Пустой состав и восстановление аддонов сохраняют работающий оконник. При ошибке ядра показана ошибка с перезапуском, а не иной интерфейс.
- [x] Миграция нескольких официальных VSX-версий не создаёт дубликатов; оконные профили используют обновлённую версию.
- [x] Отсутствующая необязательная библиотека выбранного аддона блокирует только его зависимых, а не весь состав.
- [x] На изолированной копии сохранённого профиля с четырьмя проектами проверены запуск, переключение вкладок, пустой состав и старое значение режима.

## Alpha.5: дополнения, наборы и VSX

- [x] Наборы разворачиваются в выбранные компоненты, не живут как зависимости runtime; частичный набор сохраняет установленные компоненты.
- [x] Удаляемые встроенные адаптеры: отдельные файлы регистрации, восстановление, сохранение системных инструментов; тот же путь работает через фасад нескольких окон.
- [x] Отключение: немедленно убираются поля настроек, умный ввод, notebook-view, подсказки и поздняя диагностика отключённого clangd-компонента. Переключения состава сериализованы.
- [x] Notebook открывается ячейками в ручном проекте; показ ячеек отделён от установки интерпретатора. Требования шаблона остаются в проекте.
- [x] Комментарии около функций доступны в hover и структуре; состав, прокрутка и соседние вкладки сохраняются.
- [x] Одинаковый оконный режим при смене проекта восстанавливает раскладку без перезагрузки; статус готовности не выставляется до окончания переключения.
- [x] VSX: реальное выполнение проверяемых Node-расширений, команды/настройки/diagnostics и редакторные providers; согласие на частичную совместимость, перечень отсутствующих API, политика совмещения анализа.
- [ ] Неограниченная совместимость с VS Code. Отсутствующие API и границы проверок перечислены в [VSX-COMPATIBILITY.md](VSX-COMPATIBILITY.md).

Проверки alpha.5/alpha.6: `work/addon-cycle-20261031`. Отдельно записаны source UI,
проверки Node-хоста, публичный VSX-пакет, упакованный и установленный EXE.
При ошибке внешней сети повторяется нужная проверка, её нельзя заменять
утверждением об успешной проверке сети. Unit-тест доставки optional assets
использует закреплённые байты с проверкой хеша; живой режим включается через
`DEVFORGE_TEST_LIVE_ASSETS=1`.

## Регрессионные сценарии текущего прохода

- [ ] CMake-проект: создание → видимая папка сборки → настоящая сборка → повторное открытие.
- [ ] Существующий CMake-проект: создание `build` внешним процессом и обновление проводника.
- [ ] Пользовательская папка сборки: относительный путь, вложенный путь, пробелы в пути.
- [ ] Python/notebook/пустой проект: папка сборки появляется только по конфигурации или фактическому существованию.
- [ ] Подключение EditorConfig, форматтера и настроек Python одним нажатием без предпросмотра.
- [ ] Подключение поддержки CMake к пустому/смешанному проекту; проверка конфигураций и кнопок запуска.
- [ ] Шаблон: конфликт файла → явный выбор замены → исходный файл защищён до согласия.
- [ ] Шаблон: отсутствующая зависимость → установка/понятная ошибка → повторное применение.
- [ ] Шаблон с уже совпадающими файлами: повторное применение не завершается ошибкой.
- [x] Аддон: включить → проверить функцию → выключить → проверить исчезновение функции → включить снова.
- [x] Аддон: переключить проект → перезапустить приложение → состояние соответствует выбору.
- [x] Пак и зависимости: частичный выбор; отключение зависимости с понятным списком последствий.
- [x] Импорт локального аддона: согласие, регистрация шаблона/сниппета, отключение и удаление.
- [ ] Оба режима интерфейса: файлы, дополнения, консоль, терминал, проблемы переключаются без потери вкладок.
- [ ] Перетаскивание, привязка, размеры и повторное нажатие боковой кнопки сохраняют прежнюю логику.
- [ ] Сохранение, внешнее изменение, длинные пути, закрытие и полный повторный запуск.
- [x] Проверка собранного и установленного приложения, а не только исходников.

## Правила приёмки

1. Сначала воспроизвести дефект и записать причину. Для серьёзных повторяющихся
   дефектов добавить проверку, падающую до исправления.
2. Backend-тесты дополнять настоящим сценарием интерфейса. Успешная регистрация
   аддона ещё не подтверждает доступность его функции пользователю.
3. Результат связывать с версией/коммитом и путём отчёта. Внешняя сеть, физическая
   клавиатура и другие непроверенные условия указываются отдельно.
4. После исправлений выполнить затронутые сценарии, затем общие регрессии.
   Не менять дизайн или оконник ради прохождения теста.
5. Перед обновлением сохранить данные; проверить установку и повторный запуск.
   Незавершённые пункты остаются открытыми; «все тесты прошли» не означает
   отсутствие всех ошибок.
6. По просьбе пользователя каждое исправление сопровождать проверкой аналогичных
   мест, использующих тот же механизм. Например: все пути удаления, оба режима
   панелей, все служебные вкладки, завершение всех видов объявлений, подсказки
   разных типов. Проверять результат действия, а не только наличие функции.

  Эти сетевые проверки не засчитываются как подтверждённые для финальной сборки.

  `work/electron-repair/source-verified.json`: 44/44.

  включая реальную сборку GCC/CMake, а не только проверки исходных функций.

  `work/electron-repair/installed-verified.json`: 44/44. Совпадение 604 файлов
  записано в `installed-payload.json`. Резервная копия исходников и конфигураций
  проверена по SHA-256; единственная намеренная правка профиля — видимый `build`.
- Найдена и исправлена гонка: отмена фонового Python-анализа останавливала
  административную установку компонентов. Остановка проекта теперь прерывает
  анализ и форматирование, установка отменяется при закрытии приложения.
- UI работает вне экрана, со свежим временным профилем; пользовательские проекты
  не используются как тестовые. Эти результаты отдельно от установки пользователю.
