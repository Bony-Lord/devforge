# Рабочие области VSX в Windows

DevForge открывает сохранённые файлы `.code-workspace` через управление
проектами → **Открыть рабочую область…** и через команду расширения
`vscode.openFolder`. В проводнике отображаются отдельные именованные корни.
Относительные пути, локальные `file:` URI, комментарии JSONC и отсутствующие
папки поддерживаются; одинаковые физические корни не дублируются.

Code OSS получает настоящий файл рабочей области. Расширения используют
`workspaceFolders`, `workspaceFile`, `getWorkspaceFolder`, `asRelativePath`,
`findFiles`, настройки рабочей области и отдельной папки. Добавление и удаление
корней сохранённой области через `updateWorkspaceFolders` обновляет обычный
проводник и доступ редактора к файлам. Остальные настройки и комментарии файла
сохраняются. Внешние изменения файлов и списка корней подхватываются автоматически.
Если внешний редактор временно оставил некорректный JSONC, нативная часть сохраняет
последние известные корни и сообщает об ошибке без перезаписи файла.

Обычные редакторы DevForge открывают и сохраняют исходники из дополнительных
папок. Создание файлов, мастер классов, вставка, локальная история,
переименование, корзина и восстановление учитывают корень. Удаление корня из
области оставляет открытый файл только для чтения. Корневую папку нельзя случайно
перетащить или удалить как обычный файл; пункт меню убирает её из области.
Удаление записи области из списка проектов сохраняет связанные папки.

Пересекающиеся папки и области разделяют проверку занятости: второе окно
предлагает режим чтения. Он защищает каждый корень и сам файл области.
В окне чтения не запускаются Node- и worker-хосты расширений; локальный мост
команд редактора остаётся доступным. Такое окно не удерживает файловое хранилище
расширений редактирующего окна.
`workspaceState` расширения хранится отдельно для каждого проекта или файла
области и сохраняется после переключений и перезапуска.

`updateWorkspaceFolders` также работает для обычной папки и пустого окна.
При первом переходе DevForge создаёт постоянный файл области в профиле приложения
(`workspace-files/<id>/workspace.code-workspace`). Открытые вкладки, несохранённый
код, группы оконника, локальная история и конфигурации запуска сохраняются.
Настройки Code OSS уровня окна переносятся из исходной папки; настройки отдельных
папок продолжают читаться из их `.vscode/settings.json`. Уже открытое окно чтения
подхватывает переход. При конфликте с другим редактирующим окном изменение
отклоняется, а прежняя область остаётся рабочей.

Пункт **Открыть файл рабочей области** в настройках проекта открывает созданный
файл для просмотра и редактирования. JSON-аддон включает подсветку JSON с
комментариями для `.code-workspace` и `.jsonc`.

Команда Code OSS **Save Workspace As…** и пункт **Сохранить рабочую область как…**
в настройках проекта используют диалог Windows. Команда работает для сохранённой
области, обычной папки и пустого окна. При изменении расположения файла сохраняются
комментарии JSONC, относительные корни, открытые вкладки, несохранённый код,
группы оконника и нативные конфигурации запуска. Открытый редактор файла области
переходит на новый путь в той же группе. Несохранённые изменения самого файла
области попадают в новую копию; исходный файл остаётся прежним.

`workspaceState` и файлы Node-расширений в `storageUri` переносятся в новую область.
Исходное состояние остаётся доступным при повторном открытии старой области.
При замене существовавшего хранилища прежние данные сохраняются в профиле,
в `codeoss/workspace-transfer-backups`. Операция проверяет свободное место и
блокировки каталогов. При неудаче возвращается прежняя область и её хост расширений;
внешние изменения исходного файла или назначения не перезаписываются.
Занятое другим редактором назначение отклоняется. Отмена диалога ничего не меняет;
выбор текущего файла выполняет обычное сохранение. Уже открытое окно чтения
подхватывает новый путь, сохраняя доступ только для чтения.

Перезапуск редактора ждёт освобождения `storageUri` прежним Node-хостом до 20 секунд,
прежде чем upstream выберет запасной каталог. Проверка настоящей блокировки и
владельца сохранена. Это предотвращает временное исчезновение файлов расширения
при быстром обновлении окна. Текущая проверка переноса `storageUri` использует
настоящее Node-расширение; отдельное файловое хранилище web-worker расширений
ещё требует собственного сценария проверки.

Проверки запускаются из корня репозитория с уже подготовленными зависимостями:

```powershell
node desktop/compat/prepare.cjs
node desktop/workspace-regressions.cjs
node desktop/soak/run.cjs --app desktop --suite "VSX workspaces" --cycles 1 --minutes 5 --no-keep-awake --report-root work/workspace-suite
node desktop/soak/run.cjs --app desktop --suite "VSX workspace creation" --cycles 1 --minutes 5 --no-keep-awake --max-memory-mb 3072 --max-disk-mb 256 --report-root work/workspace-creation-suite
node desktop/soak/run.cjs --app desktop --suite "VSX workspace Save As" --cycles 1 --minutes 5 --no-keep-awake --max-memory-mb 4096 --max-disk-mb 256 --report-root work/workspace-saveas-suite
```

Прямой сценарий выполняет 26 проверок с настоящим Node-хостом расширений и
отдельными временными проектами. JSON и снимок сохраняются в
`work/workspace-compat/`; путь можно изменить переменной
`DEVFORGE_WORKSPACE_REPORT`. `--app=C:\path\DevForge.exe` проверяет готовую
сборку. Прямой запуск сохраняет профиль для диагностики; запуск через длительный
тестер помещает его в принадлежащую прогону временную папку и очищает её после
завершения. Новые сценарии **VSX workspaces** и **VSX editor columns** включены
в очередность регрессионных проверок тестера. Сценарий **VSX workspace creation**
добавляет 23 проверки перехода из папки и пустого окна, сохранения представлений и
состояния, отклонения конфликтов, синхронизации окна чтения и остановки хоста.
Эта проверка временно открывает два полноценных окна. В примере явно заданы
лимиты в 3 ГБ суммарного рабочего набора процессов и 256 МБ временных файлов;
общие значения тестера остаются прежними. Отчёт сценария сохраняет замер памяти
и частичный журнал, если проверка остановлена по лимиту.
Сценарий **VSX workspace Save As** добавляет 20 проверок сохранения и переноса
состояния, отмены, занятых файлов, окна чтения, обычной папки и пустого окна.
В примере для него задан лимит 4 ГБ; он не меняет общие настройки тестера.
Сумма рабочих наборов процессов в отчёте включает общие страницы памяти и
не является измерением уникальной памяти приложения.

Это часть совместимости, а не обещание работы всех расширений.
Общие настройки нативной сборки/CMake пока используют каталог проекта;
оркестрация отдельных нативных целей по корням остаётся отдельной задачей.
Различия версий API клиента и Node-хоста, управление установкой из расширений,
private/proposed API и зависимости от нативного ABI также требуют дальнейшей
проверки. Существующие вкладки Code OSS и обычные группы оконника сохраняют своих
владельцев, описанных в [VSX-EDITOR-COLUMNS.md](VSX-EDITOR-COLUMNS.md).
