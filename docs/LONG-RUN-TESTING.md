# Длительное тестирование DevForge

Запустите `START-DEVFORGE-TESTS.cmd` двойным щелчком. Нужен уже установленный Node.js 22 или новее. По умолчанию тестируется установленный DevForge в течение 8 часов. `STOP-DEVFORGE-TESTS.cmd` запрашивает остановку; Ctrl+C в окне тестера делает то же самое. Завершение текущей операции и закрытие тестового приложения занимает некоторое время. `OPEN-DEVFORGE-TEST-REPORT.cmd` открывает последний отчёт.

Рабочие проекты и профиль пользователя не используются. Каждый цикл получает отдельный профиль и два маленьких синтетических проекта. Тестовое приложение работает скрыто, без захвата мыши и клавиатуры рабочего стола. После цикла оно закрывается; перед удалением временного профиля проверяются его реальный путь и маркер владельца. Уникальные доказательства сохраняются. Загрузки SDK, компиляторов и публичных расширений не запускаются.

Во время запуска Windows временно удерживается от автоматического сна через `SetThreadExecutionState`. План электропитания не меняется; запрос снимается при завершении, остановке или аварийном закрытии тестера. Экран может выключаться. Поле `power` в отчёте показывает состояние запроса. `--no-keep-awake` отключает это поведение.

## Запуск с параметрами

Из корня репозитория:

```powershell
# На сутки; память — сумма рабочих наборов процессов тестового приложения
node desktop/soak/run.cjs --hours 24 --max-memory-mb 2048 --max-disk-mb 512

# Короткая проверка установленной версии
node desktop/soak/run.cjs --steps 50 --seed check-after-update --no-regressions

# Проверка другого EXE и отдельная папка отчётов
node desktop/soak/run.cjs --app "D:\DevForge\DevForge.exe" --report-root "D:\DevForgeTests"

# Та же папка обязательна при остановке нестандартного запуска
node desktop/soak/run.cjs --stop --report-root "D:\DevForgeTests"

# Повтор сохранённой последовательности в новых синтетических проектах
node desktop/soak/run.cjs --replay "D:\DevForgeTests\<запуск>\findings\<id>\replay.json"

# Отдельный набор; находки набора тоже повторяются через --replay
node desktop/soak/run.cjs --suite "Editors and windows"

# Проверка самого поиска обрезки: вставляется заведомо обрезанная тестовая кнопка
node desktop/soak/run.cjs --self-check --steps 1 --no-regressions
```

`--app` можно не указывать после обновления: используется обычный путь установки. Для разработки можно передать каталог `desktop`, если его Electron уже установлен. `--help` перечисляет параметры, `--list` — сценарии. CMD-файл запуска принимает те же параметры.

## Что проверяется

В начале каждого цикла проходят все сценарии, затем запускаются их случайные сочетания. Seed фиксируется. Проверяются вкладки и соответствие модели редактора, ввод и сохранение с Undo/Redo, Markdown/JSON/C++, изменение размера и масштаба, поиск, настройки, панели, дополнения, переименование, копирование, корзина и восстановление, внешние изменения, ячейки ipynb, переключение проектов, перезагрузка и разделение редактора. Запуск кода ноутбуков в случайном проходе не выполняется.

Между циклами, не чаще раза в 90 минут, последовательно запускаются существующие регрессии VSX с локальным тестовым расширением и проверки редакторов/окон. Полный UI-набор добавляется в ротацию при наличии проверенного локального кэша Python-инструментов (`--tool-cache`); сетевой магазин из него исключён. Результаты и число выполненных проверок отображаются в `suites`. Большой набор тоже подчиняется лимиту памяти: при прерывании сохраняется частичный журнал, завершённым он не считается. Для полного прохода ему может потребоваться увеличить `--max-memory-mb`. `--no-regressions` отключает эту ротацию.

Визуальный анализ ищет обрезанные и перекрытые элементы, выход SVG за область значка, окна за экраном и лишнюю горизонтальную прокрутку. Сохраняются обычный скриншот, вариант с отметками и геометрия. Эталонный вид редактора также сравнивается со снимком предыдущих запусков при одинаковых размере, теме, языке и шрифте. Первый снимок — **исходная точка сравнения, а не утверждение, что оформление правильное**. Намеренное изменение дизайна тоже может попасть в подозрения. Эталоны лежат в `baselines`; новый каталог отчётов создаёт новый набор эталонов.

## Отчёты и ограничения ресурсов

По умолчанию отчёты находятся в `%USERPROFILE%\DevForgeTests`. Этот путь одинаков при запуске из Codex и обычного проводника Windows. В каждом запуске есть `index.html`, `status.json`, `actions.jsonl` и каталог `findings`. `latest.json` указывает на последний запуск. Отчёт разделяет наблюдаемые сбои приложения (`bug`), визуальные подозрения (`visual`), недоступные привязки/возможности (`adapter`), превышение ресурсов и ошибки инфраструктуры. Пропущенный сценарий не считается успешным. Одинаковые находки объединяются со счётчиком повторов. Для разбора достаточно передать путь к папке запуска в этот чат.

По умолчанию приложение перезапускается после 120 действий либо 15 минут. Суммарный рабочий набор его процессов проверяется примерно раз в 30 секунд: при превышении 2048 MiB цикл завершается. Это периодическая проверка, не жёсткая квота Windows; кратковременный пик возможен. Тестер и операционная система дополнительно используют память. Размер всего каталога отчётов ограничен 512 MiB, включая прошлые запуски и текущий профиль. При достижении лимита тестирование останавливается, накопленные доказательства не удаляются. Отдельный набор регрессий ограничен 12 минутами; одновременно работает только один тестовый экземпляр приложения. Старые отчёты можно перенести вручную или выбрать другой каталог.

Сценарии ограничены по числу шагов, времени и объёму; при накоплении 200 разных находок запуск тоже останавливается для разбора. Они не перебирают математически все варианты и не доказывают совместимость каждого расширения VSX. Оборудование, сетевой магазин и сторонние расширения требуют дополнительных сценариев. Визуальные находки требуют просмотра человеком. Seed и журнал позволяют повторить действия, но гонка или другой внешний фактор могут не повториться.

Визуальное подозрение записывается, только если оно сохраняется в двух проверках с интервалом 250 мс. Элемент, центр которого уже скрыт обрезающим контейнером, не считается перекрытым соседней панелью. Проверки этих правил выполняются в настоящем Electron-рендерере. В режиме повтора поле `replay.completed` означает выполнение всей последовательности, а `replay.targetObserved` — повторное обнаружение исходной находки. Если лимит памяти или другой предел прервал повтор, статус будет `interrupted`; такой повтор не подтверждает исправление.

## Обновления приложения

Сценарии, генератор, анализ оформления, запись доказательств и HTML-отчёт отделены от конкретного DOM/API приложения. Все имена внутренних методов, доступные названия и резервные CSS-селекторы собраны в `desktop/soak/adapter.js`. Сначала используются доступные названия и роли, затем резервные привязки. Адаптер сообщает версию протокола и доступные возможности. В отчёте записываются версия приложения, хеш адаптера и seed.

Обычно после обновления достаточно запустить тот же скрипт. При переименовании внутренних API меняется адаптер, остальные части сохраняются. При существенной перестройке интерфейса обновить привязки всё же может потребоваться; это отображается отдельно от сбоя приложения. Новая функция добавляется отдельным сценарием. Для проверки изменений тестера:

```powershell
node --test desktop/tests/soak.test.cjs
node desktop/soak/run.cjs --steps 40 --no-regressions --seed adapter-check
```

Проверки VSX также включают **VSX editor columns** (группы редактора) и
**VSX workspaces** (сохранённые рабочие области с несколькими папками). Для
отдельного запуска на исходниках:

```powershell
node desktop/soak/run.cjs --app desktop --suite "VSX workspaces" --cycles 1 --minutes 5 --no-keep-awake --report-root work/workspace-suite
```

Область проверки и оставшиеся ограничения описаны в
[VSX-WORKSPACES.md](VSX-WORKSPACES.md) и
[VSX-EDITOR-COLUMNS.md](VSX-EDITOR-COLUMNS.md).
