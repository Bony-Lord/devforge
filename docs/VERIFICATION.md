Отдельный instrumentation APK планшет отклонил с `INSTALL_FAILED_USER_RESTRICTED`; пользователь сообщил, что не нажимал отказ. Защита установщика не отключалась. В отдельном малом проекте медиана переключений C++/CMake составила 100 мс (максимум 148 мс); WebView rAF — 16,7 мс по медиане и 16,7 мс p95. Это один прогон, не полный бенчмарк нативного ввода или всех проектов.

Отдельно проходит Android release lint. CI запускает их вместе с прежними тестами. Современный target SDK и готовые настольные сборки пока не реализованы — [границы платформ](PLATFORMS.md).

## Задержка анализа

Сравнивался небольшой прогретый пример с `std::vector`, по три изменения и три запроса автодополнения. До исправления передача ошибок в нативный редактор занимала **1043–1090 мс** от изменения модели. После разделения диагностики, семантической подсветки и inlay-подсказок — **331–368 мс**. Выборки: [verification-analysis-latency.json](../verification-analysis-latency.json).

Это время до отправки диагностики Android-редактору, а не измерение появления пикселей. Отдельная instrumentation-проверка получила настоящую ошибку clangd в нативных DiagnosticRegion за 274 мс. Результат зависит от проекта, заголовков, индекса и температуры устройства. Три запроса автодополнения после исправления заняли 191–219 мс; это не доказательство ускорения всех подсказок. Устаревшие запросы отменяются при наборе; подсказки типов запрашиваются вокруг видимой области.

Нативное представление приняло клавишу за 49 мс, пока JS WebView был занят 2200 мс. Время включает инструментальную доставку ввода; это также не кадровый бенчмарк.

## Воспроизведение

Нужны debug-сборка, разрешённый ADB и Python с `websocket-client`. Выберите отдельный тестовый проект `input-check-*`: новые сценарии отказываются менять проекты с другими именами. Они перезаписывают только выбранный тестовый проект. Координаты экранных клавиш в `device_native_input.py` соответствуют наблюдавшейся QWERTY-раскладке RMX3951: для другого устройства их нужно настроить.

```sh
python tests/device_native_input.py
python tests/device_native_features.py
python tests/device_native_updates.py
python tests/device_analysis_latency.py analysis-sample.json
./gradlew :gesture-tests:assembleDebug
adb install -t -r gesture-tests/build/outputs/apk/debug/gesture-tests-debug.apk
adb shell am instrument -w com.forgex.gesturetests/dev.forge.ide.NativeInputInstrumentation
adb shell am instrument -w -e smart true com.forgex.gesturetests/dev.forge.ide.NativeInputInstrumentation
adb shell am instrument -w -e tabs true com.forgex.gesturetests/dev.forge.ide.NativeInputInstrumentation
adb uninstall com.forgex.gesturetests
node tests/protocol.test.cjs
```

Release APK отключает `debuggable` и удалённую отладку WebView; после установки отдельно проверяется запуск. CI проверяет синтаксис JavaScript/Python, шесть проверок GDB/MI-парсера и компиляцию Android-хоста. CI не заменяет настоящую клавиатуру и жесты.

## Предыдущие проверки и границы

[verification.json](../verification.json), [verification-tools.json](../verification-tools.json), [verification-workspace.json](../verification-workspace.json) и [verification-keyboard.json](../verification-keyboard.json) содержат 52 проверки прототипа **0.1** за 19 октября. Они сохраняются как история проверки компиляторов, стандартов, CMake, Git, GDB и раскладки. Это не повторная проверка всех функций после замены редактора и не подтверждение исправности всех сценариев IME.

Набор стандартов подтверждал принятие флагов, а не полную реализацию C++23/C++26. Неиспользуемость публичных функций нельзя всегда определить из одного файла.

Физический планшет и внешняя клавиатура отдельно не проверены. Широкая раскладка проверялась изменением размера WebView, сочетания — инструментальным вводом. Другие Android/IME, длительная работа с крупными проектами, системные диалоги импорта/экспорта и все варианты Git-аутентификации требуют дополнительных проверок. Доступ к общей памяти не обходит ограничения Android для чужих приватных папок.

Новый снимок редактора в README получен с экрана телефона. Снимки раскладки и отладчика 0.1 явно помечены как предыдущая версия. Границы функциональности перечислены в [README](../README.md#границы-текущей-версии).
