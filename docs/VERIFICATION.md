# Проверка версии 0.1.0

Проверки выполнены 19 октября 2026 года на физическом **realme RMX3951, Android 16, ARM64**, без root. Компиляторы и анализатор запускались внутри приложения; ответы не подменялись тестовыми данными.

| Набор | Проверенный результат | Отчёт |
|---|---|---|
| Основной сценарий | 24/24: GCC и Clang, C/C++, запуск и stdin/args/stderr/exit, стандарты, clangd, диагностика, навигация, переименование, форматирование, история, CMake с несколькими единицами трансляции, остановка | [verification.json](../verification.json) |
| Инструменты и оформление | 15/15: GDB с остановкой на main и breakpoint, шаг 5 → 7, наблюдение 21, настоящий PTY-вывод; Git init/commit/diff/branch; два редактора и масштабы; серые неиспользуемые символы | [verification-tools.json](../verification-tools.json) |
| Рабочее место | 8/8: 38 комбинаций C/C++ стандартов и GCC/Clang, размеры 1280×800, Ctrl S, Ctrl Space, независимые клавиатурные масштабы, сохранение расположения после перезапуска | [verification-workspace.json](../verification-workspace.json) |
| Экранная клавиатура | 5/5: реальная Android IME, ввод экранными клавишами, полное и частичное перекрытие 100/50/0%, видимость курсора в конце длинного файла | [verification-keyboard.json](../verification-keyboard.json) |

Серый цвет `#6F737A` проверен по фактическим декорациям Monaco и вычисленным CSS-цветам для неиспользуемых локальной переменной, параметра, статической функции и приватного поля. Диагностику предоставлял clangd.

Проверка каждого пункта стандарта компилирует минимальную программу. Она подтверждает принятие соответствующего флага, а не полную реализацию всех возможностей C++23/C++26 в компиляторе и libc++.

Сборка APK проверена через прямой Android toolchain (`build.ps1`) и через Gradle/Android Studio project (`:app:assembleDebug`). Шесть отдельных проверок разбора GDB/MI проходят в Node.js. CI проверяет JavaScript, Python, протокольный парсер и компиляцию Java-хоста; CI не заменяет физические проверки Android.

## Воспроизведение на устройстве

Нужны debug-сборка, разрешённый ADB и Python с `websocket-client`. Переменная `ADB` позволяет указать путь к adb. Скрипты управляют только установленным приложением и создают отдельные тестовые проекты.

```sh
python tests/device_acceptance.py
python tests/device_tools_acceptance.py
python tests/device_workspace_acceptance.py
python tests/device_keyboard_acceptance.py
node tests/protocol.test.cjs
```

Release APK отключает `debuggable` и удалённую отладку WebView. После установки release дополнительно проверяется запуск приложения.

Проверка непосредственного ввода экранными клавишами запускалась с `--tap-q 60 1825 --tap-space 540 2270` после наблюдения текущей раскладки Yandex Keyboard на RMX3951. Для другого устройства нужны координаты его клавиш; без этих параметров проверяется геометрия клавиатуры и видимость курсора.

## Что пока не подтверждено

- Настоящий планшет и физическая клавиатура: размеры планшета эмулировались в WebView телефона, сочетания клавиш отправлялись через Chrome DevTools Protocol.
- Другие версии Android, процессоры и прошивки, рабочие профили, длительная работа с большими проектами.
- Системные диалоги импорта/экспорта Android, приватная Git-аутентификация и все варианты сетевого клонирования не покрыты автоматическими сценариями.
- Полный набор возможностей настольного CLion не воспроизводится. Актуальные границы описаны в [README](../README.md#границы-текущей-версии).

Скриншоты в README получены из работающего WebView Android-приложения при размере 1000×800. Геометрия также проверялась при 1280×800. Это проверка адаптивной раскладки, а не фотография физического планшета.
