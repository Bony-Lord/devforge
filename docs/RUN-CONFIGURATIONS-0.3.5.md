# Запуск, профили и runtime-диагностика в 0.3.5

Это Android preview, а не заявление о полной совместимости с CLion или готовности SDK аддонов.

## Выбор и редактирование

Справа в верхней панели находятся выбор запуска и профиля. Редактор открывается через значок настроек или пункт «Изменить конфигурации…». Слева — список с поиском, добавлением из типа, копированием, удалением и перестановкой; справа — поля выбранного элемента. CMake-профили редактируются отдельно от параметров запуска. Есть «Применить», «ОК» и запуск без повторного поиска конфигурации. Щелчок за пределами диалога закрывает его без применения черновика.

В конфигурации задаются цель, исходник или исполняемый файл, аргументы с обычными кавычками, рабочая папка и окружение. Рабочая папка по умолчанию — корень проекта, а не каталог сборки. Поддерживается `$PROJECT_DIR$`. Профиль хранит компилятор, стандарты C/C++, Debug/Release, каталог сборки, дополнительные флаги и параметры CMake. Аргументы и окружение передаются как данные, без неявного исполнения оболочкой.

Документ проекта — `.cpp-studio/configurations.json`. Кнопка JSON показывает его без потери неизвестных полей. Некорректный документ не подменяется молча: редактор сообщает ошибку, а обычные файлы проекта остаются доступными. Эти файлы не импортируют настройки `.idea` и не являются реализацией IntelliJ.

## Типы проектов и сборка

Новые C/C++ проекты получают CMakeLists, исходник и конфигурации CMake, текущего файла и всех исходников, а также профили Debug/Release. «Пустой / вручную» создаёт конфигурацию без обязательного CMakeLists и исходника.

Ручной тип позволяет задавать `buildCommands` как массивы argv и `runCommand` как argv. Например:

```json
{
  "type": "custom",
  "buildCommands": [["/system/bin/sh", "-c", "printf ready > generated.txt"]],
  "runCommand": ["/system/bin/sh", "-c", "cat generated.txt"],
  "workingDirectory": ".",
  "environment": {},
  "buildBeforeRun": true
}
```

Это фрагмент конфигурации: общие `id`, `name`, `profile`, `source`, `target`, `args` и `executable` сохраняются в полном документе. Оболочка запускается только при явном указании `/system/bin/sh -c`. Команды работают с правами приложения. Поддержка произвольных языковых провайдеров и Python/notebook UI остаётся в [плане SDK](ADDONS-ROADMAP.md).

CMake собирает выбранную цель через `--target`. Реальный путь программы определяется по публичному CMake File API, поэтому `OUTPUT_NAME` и вложенный `RUNTIME_OUTPUT_DIRECTORY` не требуют угадывать имя `app` в корне build. У разных профилей отдельные каталоги; инструментированная отладка не загрязняет обычную сборку.

Код завершения программы отделён от результата компиляции. Например, `return 7` из `main` даёт код возврата 7 после успешной сборки с кодом 0.

## Предупреждения во время отладки

В Debug-профиле по умолчанию включены проверяемые UBSan-нарушения: выход за известные границы массива, переполнение знакового целого, сдвиги, null/alignment. GCC использует уже поставляемый compiler-rt через локальную спецификацию линкера; компилятор автоматически не заменяется на Clang. В профиле Clang можно выбрать AddressSanitizer + UBSan для дополнительных проверок памяти.

Поддерживаемая восстанавливаемая диагностика выводится как warning, с переходом к исходнику и жёлтым маркером. `-fsanitize-recover` и `halt_on_error=0` позволяют продолжение, когда runtime допускает его. Режим можно выключить в профиле. В Android/GDB автоматическая символизация runtime отключена: стек просматривается средствами GDB.

**Неинициализированные значения проверяет статическая диагностика компилятора/clangd.** Это не MemorySanitizer: Android runtime MSan не входит в поставку. UBSan не обнаруживает все чтения неинициализированной памяти или все выходы по указателю. ASan тоже не даёт полного MSan-покрытия. Настоящие SIGSEGV/SIGABRT по-прежнему останавливают отладчик; переименование такого сигнала в warning не сделает повреждённую программу продолжаемой.

Источники поведения: [конфигурации CLion](https://www.jetbrains.com/help/clion/run-debug-configuration.html), [CMake Application](https://www.jetbrains.com/help/clion/run-debug-configuration-application.html), [профили CMake](https://www.jetbrains.com/help/clion/cmake-profile.html), [CMake File API](https://cmake.org/cmake/help/latest/manual/cmake-file-api.7.html), [GCC instrumentation](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html), [UBSan](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html), [ограничения MSan](https://clang.llvm.org/docs/MemorySanitizer.html). Код и фирменные ресурсы CLion не включались.
