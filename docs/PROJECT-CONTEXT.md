# Проекты, аддоны и действия — 0.5 alpha

Проект может выбирать собственный набор аддонов и режим интерфейса. Общий набор остаётся настройкой по умолчанию для остальных проектов. Конфигурации запуска определяют действия по отдельности; тип открытого файла не подменяет выбранную конфигурацию.

Общий документ находится в `.devforge/project.json`. Минимальный Python-пример:

```json
{
  "version": 1,
  "projectType": "python",
  "active": "main",
  "addons": {
    "mode": "project",
    "requested": ["studio.pack.python", "studio.pack.essentials"]
  },
  "interface": { "mode": "simple" },
  "profiles": [{
    "id": "python",
    "name": "Python",
    "kind": "interpreter",
    "environment": {}
  }],
  "configurations": [{
    "id": "main",
    "name": "Main",
    "type": "python",
    "profile": "python",
    "source": "main.py",
    "target": "",
    "args": [],
    "environment": {},
    "workingDirectory": ".",
    "executable": "",
    "buildBeforeRun": false,
    "actions": { "run": { "provider": "python.run" } }
  }]
}
```

Здесь нет действий `build` и `debug`: их кнопки скрыты, команды отсутствуют в палитре, горячие клавиши ничего не запускают. В редакторе конфигураций можно назначить `python.check` действию сборки. `buildBeforeRun: true` запускает выбранную сборку перед запуском или отладкой; ненулевой код прекращает цепочку. Провайдер недоступного аддона также скрывает кнопку. Если провайдер сборки задан, но отключён, запуск с включённой предварительной сборкой сообщает об этом.

Официальные аддоны регистрируют действия через `actionProviders` с capability `projects.actions`. Провайдер указывает идентификатор, вид действия, локализованное название, значок и требования к функции/компилятору; реализация принадлежит проверенному хосту. Поддержаны C/C++, Python, все ячейки ноутбука и ручные argv-команды. Это основа расширения новыми языками; исполняемые сторонние моды пока не доступны в SDK пакетов данных 0.1.1.

`addons.mode: "inherit"` возвращает общий состав. Открытие проекта не скачивает недостающие инструменты: их установку пользователь запускает в менеджере. Если профиль нельзя активировать, IDE показывает причину и включает пустой состав, сохраняя запрошенный список в документе проекта.

`interface.mode` принимает `inherit`, `simple`, `windows`. Оконный режим требует аддон `studio.window-manager`. Раскладки сохраняются отдельно по корню проекта в локальных настройках устройства: геометрия телефона не переносится в Git на компьютер. Смена оконного рабочего пространства пока выполняется через сохранение документов и перезапуск интерфейса.

Старый `.cpp-studio/configurations.json` читается с восстановлением прежних C/C++-действий. При следующем сохранении создаётся `.devforge/project.json`; прежний файл сохраняется. В новых документах пропущенные действия остаются отсутствующими.
