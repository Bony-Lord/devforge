# SDK аддонов: preview 1 / API 0.1.0

В Android 0.3.8 появилась работающая первая часть SDK: переносимое ядро, проверка манифестов, подбор зависимостей и версий, управляемый жизненный цикл, профиль и режим восстановления. В **Настройки → Аддоны** доступны два встроенных официальных примера: команды навигации и контрастные границы. По умолчанию они отключены. Они включаются без перезапуска; отключение удаляет команды и возвращает цвета текущей темы.

Это ещё не маркетплейс или загрузчик стороннего кода. GCC/CMake продолжают использовать проверенный загрузчик tool packs из 0.3.7. Оконник, Git, clangd и клавиатуры пока встроены. Сторонние ZIP/JavaScript/native-модули не исполняются. Полный план находится в [ADDONS-ROADMAP.md](ADDONS-ROADMAP.md).

## Разделение ответственности

`app/src/main/assets/ui/addon-core.js` не зависит от DOM, Android, C/C++, редактора, сети или файловой системы. Его можно использовать в будущих настольных хостах и проверять обычным Node.js. Это переносимость ядра SDK; готовые приложения для Linux/Windows/macOS из этого не следуют.

Хост объявляет именованные точки расширения и необходимые возможности. В этой поставке реально подключены `commands → ui.commands` и `themes → ui.theme`. Другие точки можно объявить через `Registry`; редакторы документов, языки, окна, конфигурации, процессы и middleware ещё требуют собственных контрактов и адаптеров. Регистрация имени сама по себе не реализует такую функцию.

`addons.js` — Android/WebView-адаптер и список доверенных встроенных фабрик. Он выдаёт узкий контекст `{manifest, signal, contribute, use}`. Команды задаются данными и выполняются через разрешённые действия хоста; темы меняют ограниченный список цветовых переменных. В контекст не передаются `ForgeNative`, `forge`, файловые дескрипторы или функции запуска процессов.

**Граница доверия:** встроенные фабрики работают в том же JavaScript-контексте, поэтому capability-проверки не являются песочницей. Произвольный скрипт мог бы обратиться к глобальным объектам. До появления изолированного загрузчика и проверенного транспорта возможностей сторонний исполняемый код загружать нельзя. Таймаут ограничивает асинхронную активацию; бесконечный синхронный цикл доверенного скрипта он прервать не может.

## Манифест

```json
{
  "schemaVersion": 1,
  "id": "example.navigation",
  "version": "1.0.0",
  "api": {"min": "0.1.0", "maxExclusive": "0.2.0"},
  "platforms": ["android", "windows", "linux", "macos"],
  "name": {"ru": "Навигация", "en": "Navigation"},
  "license": "MIT",
  "capabilities": ["ui.commands"],
  "dependencies": {},
  "conflicts": {}
}
```

Идентификатор имеет пространство имён, например `example.navigation`. Версия — три целых компонента без ведущих нулей, prerelease и build-суффиксов. API 0.1.0 намеренно использует явные интервалы `{min,maxExclusive}` или точную строку `"1.0.0"`; синтаксис npm `^`, `~`, `*` не поддерживается. Пустой объект означает любую версию. Зависимости и конфликты — отображения ID в такие интервалы. Неизвестные поля манифеста сохраняются и замораживаются вместе с остальными данными.

Решатель выбирает наиболее новые совместимые версии, учитывая все ограничения; при конфликте пробует предыдущие варианты. Отсутствующая зависимость, несовместимый API/платформа, цикл, конфликт и повтор одной версии отклоняют план. Количество пакетов, требований, размер манифеста и число шагов поиска ограничены. Для стабильной установленной конфигурации профиль может фиксировать точную версию: `[{"id":"example.navigation","version":"1.0.0"}]`.

## Жизненный цикл

```js
function activate(ctx) {
  ctx.contribute('commands', 'example.navigation/focus', {
    label: {ru: 'Фокус в редактор', en: 'Focus editor'},
    action: 'editor.focus'
  });
  ctx.use(() => { /* снять собственные подписки / остановить работу */ });
}
```

Фабрика регистрируется хостом в `Map` по ключу `id@version`. Манифест не является путём импорта или инструкцией `eval`. ID вклада должен начинаться с `id/`; одинаковые вклады отклоняются, требуемая capability проверяется. `ctx.use` принимает функцию освобождения или объект с `dispose`. Можно также вернуть такой объект из фабрики.

Зависимости активируются первыми. Все изменения профиля последовательно проходят одну очередь. Если активация нового аддона падает, его вклады и уже добавленные зависимости удаляются в обратном порядке; ранее работавшие аддоны остаются. При отключении сначала отменяется `AbortSignal`, затем вызываются освобождения в обратном порядке. Ошибка одного освобождения записывается, остальные продолжаются. Регистрация после закрытия scope запрещена. Уже активную версию нельзя заменить другой без перезапуска в preview 1.

Профиль хранится в нативных настройках приложения, отдельно от настроек проекта. Хост синхронно сохраняет журнал начала активации перед её выполнением. Если процесс оборвался, следующий запуск сохраняет запрошенный профиль, но пропускает аддоны. В менеджере можно восстановить профиль или выключить всё. Профиль не зависит от случайного порта локального сервера WebView. Примеров несколько, именованные пользовательские профили и перенос их между устройствами ещё не добавлены.

## Проверки и следующие шаги

`node tests/addon-core.test.cjs` проверяет версии, зависимости, циклы, конфликты, разрешения, откат, очистку, очереди, восстановление и таймаут. `tests/device_addons_038.py` проверяет реальную интеграцию на отдельном тестовом проекте: команды/цвета, параллельные переключения, холодный запуск, прерванную активацию и отключение. Проверки Android требуют явно указанного `input-check-*` проекта и не предназначены для пользовательских документов.

Дальше: изолированные UI/background/native-контракты, подписанный каталог, установка с staging и атомарной активацией/откатом, миграция tool packs, универсальные языковые и run/debug-провайдеры. Текущий загрузчик native-пакетов проверяет архив и файлы, но не обеспечивает транзакционный откат всех уже заменённых файлов при ошибке распаковки; сторонние native-пакеты через него не разрешены. Python/ipynb остаются следующими языковыми пакетами по плану.
