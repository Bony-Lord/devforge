# SDK аддонов: preview 2 / API 0.1.1

Приложение теперь называется **DevForge**. В 0.4.1 появились [менеджер с частично выбранными паками, установка по HTTPS, согласие и доверие папке](DEVFORGE.md). Внутренние идентификаторы SDK и формат пакетов сохранены для совместимости.

В 0.5 alpha добавлены [проектные составы и провайдеры действий](PROJECT-CONTEXT.md), официальные Python/notebook-модули и общий desktop backend. В Android alpha.2 инструменты используют [одно нативное окружение и данные .studio-toolpack](MODULAR-RUNTIME-0.5.md), без APK-подтверждения для каждого инструмента. Контейнер данных ZIP/JSON переносим; его нативные ссылки и содержимое зависят от ABI и хоста. Это отдельная поставка официальных инструментов; сторонний .studio-addon по-прежнему является переносимым пакетом данных API 0.1.1. Поддержка произвольного исполняемого кода сторонних модов этим этапом не добавлена.

Android 0.4.1 добавляет [мастер на основе состава аддонов](ONBOARDING-0.4.1.md). Точка `setupFields → settings.fields` позволяет официальным модулям объявлять поля `choice`, `number`, `toggle`, `text` с ключом, локализованной подписью, значением по умолчанию и ограничениями. Ядро проверяет значения и показывает только поля выбранных модулей. Служебные ключи хоста зарезервированы; сторонний `.studio-addon` пока не получает эту возможность. Правила `languages` могут также объявлять `entryFiles`, чтобы восстановление пустой сессии выбирало подходящий стартовый файл для языка.

В Android 0.4.0 работают переносимое ядро, пакеты данных `.studio-addon`, установка/удаление с журналом отката, версии/зависимости, составные паки и адаптеры функций хоста. В **Настройки → Аддоны** есть установленные модули, встроенный официальный каталог и вкладка инструментов. Локальный файл открывается через Android SAF; перед установкой показываются источник, автор, возможности, зависимости и объём необходимых загрузок.

Модулями управляются оконник, клавиатура C++ Studio, Git, clangd, форматтер, GDB, компиляторы/инструменты, подсветки C/C++, CMake, JSON, YAML, Markdown, Shell, представления JSON/Markdown и типы проектов. Есть C/C++ pack, CMake project pack и составной Full C++ IDE pack. Дополнительно модулями стали анимации/инерция, подсказки UI, умный ввод, направляющие, автосохранение, история, поиск/замена, несколько редакторов, палитра, поиск по проекту, структура, консоль, терминал, конфигурации, шаблоны, runtime-диагностика, дополнение, ошибки, семантика и inlay hints. Всего — 47 модулей функций/языков/паков/runtime и два прежних демонстрационных аддона. Отключение оконника требует перезапуска интерфейса; схема окон и открытые документы сохраняются. Отключение клавиатуры возвращает системную, сохраняя выбор пользователя для повторного включения.

**Что остаётся встроенным:** реализации оконника и Android-клавиатуры и адаптеры хоста пока находятся в APK. Это рабочие модули SDK с зависимостями и lifecycle, но их исполняемый код ещё не скачивается отдельно. GCC/CMake/Clang/clangd/GDB/Git скачиваются прежними проверяемыми tool packs, теперь связанными с графом аддонов. Удалённого маркетплейса и загрузчика стороннего JavaScript/DEX/native-кода ещё нет. [Полный план](ADDONS-ROADMAP.md).

## Пакеты данных, установка и версии

Файл `.studio-addon` — JSON с `format: "cppstudio.addon"`, `formatVersion: 1`, `manifest` и массивом `contributions`. Импорт через «Из файла…» не требует доступа ко всей памяти. Один пакет ограничен 256 КиБ, установленная библиотека — 128 версиями и 2 МиБ данных. Пакеты не содержат путей распаковки, скриптов, HTML, CSS или URL для исполнения.

Локальные пакеты могут вносить команды из разрешённого списка и цвета интерфейса. Пак с пустым `contributions` и `capabilities` может объединять другие аддоны через `dependencies`: см. `examples/addons/cpp-workspace.studio-addon`. Самостоятельный пример темы — `forest.studio-addon`. Имена авторов локальных файлов не считаются проверенными; пространство `studio.*` зарезервировано. Встроенный официальный каталог поставляется вместе с подписанным APK, не выдаётся за сетевой маркетплейс.

Установка сохраняет библиотеку и профиль в едином снимке с предыдущим состоянием. Новые вклады готовятся отдельно и публикуются одной заменой реестра. Если активация падает, сохраняются прежние работающие вклады; если установка/обновление прервалась до подтверждения, следующий запуск возвращает предыдущие пакеты **и профиль**. Запись снимка использует проверку, fsync файла и атомарную замену, с резервной копией на случай повреждения. Это проверено на ошибках записи и на остановке процесса; аппаратное отключение питания отдельно не моделировалось.

Версии неизменяемы: другой контент с тем же ID/версией отклоняется. Новая версия хранится рядом со старой; можно переключиться обратно без перезапуска. Прямые корни профиля фиксируются точными версиями. Уже работающие версии зависимостей сохраняются, пока удовлетворяют новым ограничениям. Удаление необходимой версии блокируется. Кнопка «Удалить файлы» для native-инструмента доступна через общий менеджер; активные зависимости защищены.

## Ядро и состав приложения

«Только ядро» оставляет запуск/восстановление, менеджер аддонов, язык UI, основные настройки, проекты/файлы и простой текстовый редактор с вводом, выделением, буфером обмена, undo/redo и сохранением. Такой режим проверен после холодного запуска. Копирование/сохранение и выход из сломанного состава не зависят от необязательного пака.

Кнопка «Только ядро…» показывает список выключаемых корней профиля. Если модуль нужен другим пакам, менеджер показывает их имена и предлагает выключить зависимые корни вместе. «Удобный минимум…» заменяет состав на лёгкий пак редактирования без компиляторов, Git, clangd и оконника: подсветки C/C++, JSON, YAML, Markdown и Shell, C/C++-проекты, наша клавиатура, умный ввод, направляющие, автосохранение, история, поиск/замена, поиск файлов, подсказки, анимации, палитра и шаблоны. Он работает без native-загрузок и оставляет компактную обычную компоновку. «Полная C++ IDE…» показывает граф нового состава и объём загрузок. «Сохранить состав…» экспортирует `.studio-addon` с точными зависимостями через системный диалог Android; полученный пак можно импортировать как обычный набор.

**Степень переноса:** функции имеют отдельные манифесты, точки расширения и проверяемое отключение, однако код многих адаптеров и UI-библиотек пока загружается из APK. Базовые панели меню, доступные кнопки, шрифты, масштабирование и Android-интеграция ещё составляют оболочку. Это первый работающий конструктор, не завершённый вынос каждого элемента и байта в скачиваемый пакет. Дальнейшее физическое разделение и замена реализаций сторонними авторами требуют загрузчиков, версионируемых интерфейсов и изоляции. Эта граница намеренно отделена от реально проверенных функций.

## Первая партия модулей

| Модули | Реальное поведение |
| --- | --- |
| `studio.window-manager`, `studio.keyboard` | Оконная/простая компоновка после перезапуска UI; выбор нашей/системной клавиатуры |
| `studio.git`, `studio.clangd`, `studio.formatter`, `studio.debugger` | UI и нативные службы; отключённая служба отклоняет новые вызовы |
| `studio.tool.platform/gcc/clang/cmake/analysis/debugger/git` | Связь с установленными runtime, загрузка по зависимостям и удаление файлов |
| `studio.language.*` | Ассоциации расширений/имён с подсветкой; отключение возвращает plain text в моделях и нативном редакторе |
| `studio.views.json`, `studio.views.markdown` | Безопасное дерево JSON и текстовый просмотр Markdown, без исполнения HTML |
| `studio.project.cpp`, `studio.project.cmake` | Типы в создателе проектов, шаблоны и стартовый режим сборки |
| `studio.pack.essentials`, `studio.pack.cpp`, `studio.pack.cmake`, `studio.pack.cpp-full` | Составные наборы с явными зависимостями; базовый C/C++ pack не навязывает компилятор |

На обновлении старые функции сохраняются миграцией профиля; установленные native-инструменты повторно не скачиваются. Мастер первого запуска включает модули выбранных инструментов. Пустой проект остаётся доступен в ядре без CMake и языковых паков. `.ipynb` пока открывается как JSON; полноценный notebook/Python runtime ещё не реализован.

## Разделение ответственности

`app/src/main/assets/ui/addon-core.js` не зависит от DOM, Android, C/C++, редактора, сети или файловой системы. Его можно использовать в будущих настольных хостах и проверять обычным Node.js. Это переносимость ядра SDK; готовые приложения для Linux/Windows/macOS из этого не следуют.

Хост объявляет именованные точки расширения и необходимые возможности. Подключены `commands → ui.commands`, `themes → ui.theme`, `features → host.features`, `languages → editor.languages`, `views → editor.views`, `projectTypes → projects.types`, `runtimes → tools.runtime`. Локальные пакеты данных могут регистрировать первые две точки; остальные пока предоставляют проверенные модули из APK. Пользовательские исполняемые языковые серверы, редакторы notebook, универсальные run/debug-провайдеры и middleware ещё требуют изолированных контрактов.

`addons.js` — Android/WebView-адаптер и список доверенных встроенных фабрик. Он выдаёт узкий контекст `{manifest, signal, contribute, use}`. Команды задаются данными и выполняются через разрешённые действия хоста; темы меняют ограниченный список цветовых переменных. В контекст не передаются `ForgeNative`, `forge`, файловые дескрипторы или функции запуска процессов.

**Граница доверия:** встроенные фабрики работают в том же JavaScript-контексте, поэтому capability-проверки не являются песочницей. Произвольный скрипт мог бы обратиться к глобальным объектам. До появления изолированного загрузчика и проверенного транспорта возможностей сторонний исполняемый код загружать нельзя. Таймаут ограничивает асинхронную активацию; бесконечный синхронный цикл доверенного скрипта он прервать не может.

## Манифест

```json
{
  "schemaVersion": 1,
  "id": "example.navigation",
  "version": "1.0.0",
  "api": {"min": "0.1.0", "maxExclusive": "0.2.0"},
  "platforms": ["android", "windows", "linux", "macos"],
  "name": {"ru": "Навигация", "en": "Navigation"},
  "license": "MIT",
  "capabilities": ["ui.commands"],
  "dependencies": {},
  "conflicts": {}
}
```

Идентификатор имеет пространство имён, например `example.navigation`. Версия — три целых компонента без ведущих нулей, prerelease и build-суффиксов. API 0.1.1 намеренно использует явные интервалы `{min,maxExclusive}` или точную строку `"1.0.0"`; синтаксис npm `^`, `~`, `*` не поддерживается. Пустой объект означает любую версию. Зависимости и конфликты — отображения ID в такие интервалы. Неизвестные поля манифеста сохраняются и замораживаются вместе с остальными данными.

Решатель выбирает наиболее новые совместимые версии, учитывая все ограничения; при конфликте пробует предыдущие варианты. Отсутствующая зависимость, несовместимый API/платформа, цикл, конфликт и повтор одной версии отклоняют план. Количество пакетов, требований, размер манифеста и число шагов поиска ограничены. Для стабильной установленной конфигурации профиль может фиксировать точную версию: `[{"id":"example.navigation","version":"1.0.0"}]`.

## Жизненный цикл

```js
function activate(ctx) {
  ctx.contribute('commands', 'example.navigation/focus', {
    label: {ru: 'Фокус в редактор', en: 'Focus editor'},
    action: 'editor.focus'
  });
  ctx.use(() => { /* снять собственные подписки / остановить работу */ });
}
```

Фабрика регистрируется хостом в `Map` по ключу `id@version`. Манифест не является путём импорта или инструкцией `eval`. ID вклада должен начинаться с `id/`; одинаковые вклады отклоняются, требуемая capability проверяется. `ctx.use` принимает функцию освобождения или объект с `dispose`. Можно также вернуть такой объект из фабрики.

Зависимости активируются первыми. Все изменения профиля последовательно проходят одну очередь. Если активация нового аддона падает, его вклады и уже добавленные зависимости удаляются в обратном порядке; ранее работавшие аддоны остаются. При отключении сначала отменяется `AbortSignal`, затем вызываются освобождения в обратном порядке. Ошибка одного освобождения записывается, остальные продолжаются. Регистрация после закрытия scope запрещена. Замена активной версии готовится в отдельном реестре. Ошибка новой версии не удаляет старые вклады; устаревшее освобождение ресурсов не может удалить вклад новой версии. Позднее изменение живого реестра во время асинхронной активации отменяет устаревшую транзакцию.

Профиль хранится в едином нативном снимке библиотеки аддонов, отдельно от настроек проекта; прежний профиль из SharedPreferences мигрирует один раз. Хост синхронно сохраняет журнал начала активации перед её выполнением. Если процесс оборвался, следующий запуск сохраняет запрошенный профиль, но пропускает аддоны; при прерванной установке отдельно восстанавливает целый предыдущий снимок. В менеджере можно восстановить профиль или выключить всё. Профиль не зависит от случайного порта локального сервера WebView. Примеров несколько, именованные пользовательские профили и перенос их между устройствами ещё не добавлены.

## Проверки и следующие шаги

`node tests/addon-core.test.cjs` проверяет версии, зависимости, циклы, конфликты, разрешения, откат, очистку, очереди, восстановление и таймаут. `tests/device_addon_packages_039.py`, `tests/device_addon_modules_040.py`, `tests/device_addon_constructor_040.py` и `tests/device_addon_workspace_040.py` проверяют интеграцию на отдельных тестовых проектах: команды/цвета, версии и откат, холодный запуск, прерванную установку, реальные отключения служб, раскладку окон, создание/сборку CMake-проекта и представления файлов. Проверки Android требуют явно указанного `input-check-*` проекта и не предназначены для пользовательских документов.

Дальше: изолированные UI/background/native-контракты, подписанный удалённый каталог, вынос исполняемых частей модулей из APK, универсальные языковые и run/debug-провайдеры. Текущий загрузчик native-пакетов проверяет архив и файлы, но не обеспечивает транзакционный откат всех уже заменённых файлов при ошибке распаковки; сторонние native-пакеты через него не разрешены. Python/ipynb остаются следующими языковыми пакетами по плану.


## Чистая установка и предупреждение Android

При проверке с полным удалением на Xiaomi Pad 6 Google Play Защита блокировала установку из-за target SDK28. В обычном установщике можно открыть подробности и подтвердить установку; защищённое подтверждение потребовало физического действия владельца. Установка через USB дополнительно столкнулась с отказом MIUI (`INSTALL_FAILED_USER_RESTRICTED`). Это ограничение выпуска, не успешная установка без участия человека. Общая проверка Play Защиты не отключалась. Разрешение источнику «Файлы» выдавалось временно для теста и возвращено в прежнее состояние.

Переход на актуальный target SDK и современный способ запуска скомпилированных программ остаётся отдельной архитектурной задачей. Вынос бинарников в аддоны сам по себе не меняет ограничения Android и не устраняет это предупреждение.
