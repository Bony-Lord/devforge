# IDE-паки

Откройте **Дополнения → IDE-паки**. Выбор открывается отдельной вкладкой оконника:
она не заменяет открытые файлы. Состав и рекомендуемые настройки можно посмотреть
на карточке перед загрузкой. Установка показывает зависимости и условия сторонних
расширений. Подключённые компоненты затем управляются отдельно.

**IDE Base** объединяет поиск и замену, навигацию, структуру файла, историю,
автосохранение, умный ввод, направляющие отступов, разделение редакторов, палитру,
консоль, терминал, профили запуска, шаблоны файлов, описания функций, подсказки,
анимации, дерево JSON, просмотр Markdown. Математические формулы относятся к Notebook IDE и выбираются отдельно.

**Phone IDE** включает IDE Base и мобильную клавиатуру DevForge с её сочетаниями и
управлением курсором. Она исключена из обычных наборов и списка компонентов Windows.
В окне выбора Phone IDE отмечен как Android-пак; перенос приложения на Android этим
изменением не выполняется.

Языковые паки: C++ IDE, Python IDE, Notebook IDE, JavaScript / TypeScript IDE,
Rust IDE, Go IDE, Java IDE, C# IDE и Ruby IDE. C++ IDE, Python IDE и Notebook IDE
используют собственные компоненты DevForge. Остальные языковые наборы предлагают
соответствующие расширения Open VSX и открывают отдельную проверку установки.
Инструменты скачиваются только для выбранных компонентов.

Автоматическая замена наших компонентов на VSX отключена. Собственные Vim, clangd,
форматирование и анализ Python доступны снова. При обновлении профиля восстановятся
нативные провайдеры C++, ранее заменённые автоматически; последующие ручные отключения
сохраняются. Самостоятельно установленные пользователем VSX-расширения сохраняются.

Шаблоны проектов, дополнительные поля настроек и пути инструментов добавляются
включёнными владельцами. C++ IDE не включает шаблоны Python или Notebook.
Поиск, поиск и замена и палитра команд в Windows доступны постоянно.

Рекомендуемые настройки применяются один раз с сохранением уже заданных значений.
Команда пресета в палитре позволяет применить их повторно.

## VSX-зависимости собственных аддонов

Обычный аддон может объявить:

```json
"vsxDependencies": {
  "llvm-vs-code-extensions.vscode-clangd": {"min": "0.6.0"},
  "vscodevim.vim": {}
}
```

Поле находится в `manifest`. Поддерживаются пустой диапазон, `min`,
`maxExclusive` и точная версия строкой. У обычного аддона это зависимости,
у `kind: "pack"` — включаемые компоненты. Идентификаторы сохраняют исходные
имена Open VSX; внутренние `vscode.*` ссылки формируются автоматически.

Перед установкой выполняются загрузка, проверка SHA-256 и разрешение транзитивных
зависимостей. Подходящие установленные версии переиспользуются. Проверяется порядок
активации: собственный модуль может вызвать API VSX-зависимости при своём запуске.
Согласие на сторонние исполняемые зависимости запрашивается и у официального пака.
Определения вложенных паков также сохраняются, хотя сами наборы не активируются
как отдельные провайдеры.

Проверки не заменяют запуск каждого SDK и расширения: открытие карточки,
разрешение зависимостей и выполнение команд — разные уровни проверки.

В Windows поддержка VSIX/Open VSX — системный компонент. Она исключена из списков
удаляемых и неиспользуемых зависимостей. LLVM VSX больше не устанавливается
автоматически при открытии C/C++. При необходимости его можно выбрать в Open VSX.
Настройки сторонних расширений по-прежнему передаются через службы Code OSS.
