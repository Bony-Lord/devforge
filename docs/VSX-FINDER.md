# Финдер совместимости VSX

Запуск: **START-DEVFORGE-VSX-TESTS.cmd**. Остановка: **STOP-DEVFORGE-VSX-TESTS.cmd**.
Последний отчёт: **OPEN-DEVFORGE-VSX-REPORT.cmd**.

Это отдельный профиль проверки и отдельная папка `%USERPROFILE%\DevForgeVSXTests`.
Общий финдер продолжает работать независимо. По умолчанию VSX-финдер работает до
8 часов, последовательно, с порогом памяти 3 ГиБ и суммарным лимитом отчётов
512 МиБ. Учитывается также временный профиль проверки. При достижении лимита
доказательства сохраняются. При превышении памяти тестовый профиль перезапускается;
проверка памяти периодическая, поэтому возможны краткие превышения порога.
Старые отчёты автоматически не удаляются.

```powershell
# Короткий проход всех сценариев
node desktop/soak/vsx.cjs --steps 17 --no-regressions

# Длительная проверка установленной версии
node desktop/soak/vsx.cjs --hours 8

# Повышение нагрузки только при простое компьютера; один поток по умолчанию
node desktop/soak/vsx.cjs --performance idle --hours 8

# Конкретная сборка или другой диск для отчётов
node desktop/soak/vsx.cjs --app "D:\DevForge\DevForge.exe" --report-root "D:\VSXTests"

# Повтор сохранённой последовательности
node desktop/soak/vsx.cjs --replay "C:\Users\name\DevForgeVSXTests\run\findings\id\replay.json"

# Список сценариев и штатная остановка
node desktop/soak/vsx.cjs --list
node desktop/soak/vsx.cjs --stop
```

Финдер создаёт локальные VSIX с зависимостью-библиотекой, двумя версиями основного
расширения и расширением для браузерного extension host. Они выполняются настоящими
Node/worker-хостами Code OSS. Проверяются:

- команды, физическое сочетание клавиш и команды контекстного меню проводника;
- completion, hover, символы, диагностика, форматирование и сохранённые байты файла;
- языковая конфигурация, TextMate и чтение ресурсов VSIX по HTTP;
- настройки в обе стороны и поля настроек в интерфейсе;
- включение, отключение, очистка команд/диагностики/языков, удаление и установка заново;
- предупреждение о зависимых расширениях, обновление и выбор предыдущей версии;
- дерево в боковой панели, webview, браузерное расширение, перезагрузка приложения;
- живой поиск галереи и запоздавшие результаты, узкие окна и визуальные подозрения.

После прохода случайных сценариев подключаются существующие наборы проверок VSX:
анализатор и рабочие панели, файловые операции, колонки редактора, рабочие области
и галерея. В режиме простоя планировщик выбирает только сценарии и наборы VSX.

При ошибке структурного действия финдер сохраняет доказательства и пересоздаёт
свой профиль, затем переходит к ещё не проверенным сценариям. Повтор ошибки
группируется по сценарию и сообщению, независимо от номера процесса или порта.
Известные сообщения `DeprecationWarning` записываются в `environmentWarnings`,
а настоящие исключения расширений остаются находками.

Отчёт содержит журнал действий, seed, версию приложения, хеш адаптера, состояние
дополнений, снимки экрана, исходные тестовые VSIX с SHA-256 и replay. У визуальных подозрений сохраняются обычный и
размеченный снимки; они требуют проверки человеком. Запуск с `--self-check --steps 1
--no-regressions` добавляет намеренно обрезанную кнопку для проверки детектора.

Обычные проверки не требуют магазина: локальные VSIX проходят настоящую установку
и выполнение, а ответы поиска галереи контролируются тестом. Это не проверка
доступности Open VSX и не обещание совместимости со всеми опубликованными пакетами.
Публичный LLVM VSIX используется отдельно в наборе анализатора; его сбои сохраняются
как результаты проверки, а не заменяются нативным анализатором.

Пользовательские проекты, установленные дополнения, настройки и учётные данные
не копируются в тест. Архивы и действия ограничены созданным профилем, очистка
проверяет его владельца и абсолютный путь. Приложение не нужно переустанавливать
для обновления финдера. Привязки к UI/API собраны в `vsx-adapter.js`, сценарии и
отчёты используют отдельный контракт; несовпавшие привязки помечаются как `adapter`.
