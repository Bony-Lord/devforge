# Сборки DevForge для Windows

Debug и Release собираются из одних исходников и поддерживают одинаковые проекты,
дополнения, Code OSS/VSX и оконный интерфейс. Различаются диагностика и подготовка
клиентского кода. Отдельного браузера или дополнительного SDK для Debug нет.

| | Release | Debug |
|---|---|---|
| Приложение и ярлык | DevForge | DevForge Debug |
| Профиль | `%APPDATA%\DevForge` | `%APPDATA%\DevForge Debug` |
| Новые приватные проекты по умолчанию | `Документы\DevForge` | `Документы\DevForge Debug` |
| Клиент Code OSS | Минифицирован | Читаемый код и карты исходников |
| DevTools | Отключены в установленной сборке | Кнопка Debug, F12, Ctrl+Shift+I |
| Диагностика | Штатные ошибки приложения | Ошибки процессов и интерфейса, медленные операции, время старта, ресурсы процессов, локальные crash dumps |
| Запись производительности | Через отдельные инструменты тестирования | В меню Debug; до 30 секунд, кольцевой буфер 32 МиБ |

Установщики имеют разные идентификаторы Windows, поэтому версии устанавливаются
рядом. Release обновляет обычную DevForge и сохраняет её профиль. Debug начинает
с отдельного профиля: расширения и настройки одной версии не меняют другую.
Если вручную открыть одну папку проекта в обеих версиях, это будут те же файлы.

В меню **Debug** доступны DevTools (включая профили CPU/памяти и проверку DOM),
журналы, запись производительности, экспорт отчёта и снимок интерфейса. Журналы
хранятся в `diagnostics` внутри профиля Debug: три файла не более 4 МиБ каждый.
Очередь записей ограничена; при перегрузке счётчик пропущенных записей виден в
отчёте. `performance.json` заменяет предыдущую запись. Записи автоматически не
отправляются по сети. Отчёт не содержит содержимого файлов, IPC-параметров или
настроек аккаунтов; в сообщениях скрываются стандартные поля секретов и query
параметры URL. Снимок сохраняется только по команде пользователя.

## Сборка

Команды выполняются из `desktop` после подготовки закреплённых зависимостей:

```powershell
npm run build:debug
npm run build:release
# Обе версии последовательно:
npm run build:all
# Установщики из уже проверенных пакетов:
npm run installers:debug
npm run installers:release
# Или обе сборки вместе с установщиками:
node build.cjs --channel=all --installers
```

Версия берётся из `desktop/package.json`; уже существующие папки пакетов не
перезаписываются сборщиком. Для следующей поставки повышается версия. Клиент
Debug собирается в `desktop/.cache/codeoss-debug`, Release — в обычный каталог
`ui/vendor/codeoss`. Архив сервера, зависимости и источники FFmpeg используются
повторно. Пакет и установщик проверяют совпадение канала клиента и приложения;
переменная окружения не может переключить канал готовой установленной сборки.

Проверки настоящих EXE:

```powershell
node desktop/build-flavor-regressions.cjs
node desktop/unified-ui-regressions.cjs --live-gallery --app=<путь-к-EXE>
node desktop/native-stability-regressions.cjs --app=<путь-к-EXE>
```

Проверки используют временные профили и расширения-фикстуры. Обычный профиль
пользователя для тестов не запускается. Финдеру также передаётся конкретный EXE:
для подробных отчётов — Debug, для оценки поведения обычной версии — Release.
